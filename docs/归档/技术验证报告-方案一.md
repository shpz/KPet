## 关键发现：RT 像素语义（§5.3"待实测"项的答案）

**UE 的 scene capture 输出像素是「RGB 已按不透明度预乘 + alpha 存反向不透明度（1 − opacity）」**，不是常规直觉的「直线 RGB + 不透明度 alpha」：

- 背景：RGB≈0，alpha=255（反向：不透明度 0）
- 不透明球体：RGB=颜色，alpha=0（反向：不透明度 255）

源码证据（UE 5.4 `EngineTypes.h:493`，语义沿用至 5.8 实测一致）：

```
SCS_SceneColorHDR UMETA(DisplayName="SceneColor (HDR) in RGB, Inv Opacity in A")
```

`r.PostProcessing.PropagateAlpha`（5.6+ 改名 **Alpha Output**，bool）打开后，这个"Inv Opacity"语义被原样带过 tonemapper 进入 FinalColorLDR 输出。**修复只需 CPU 侧：`A = 255 - A_read`，RGB 已是预乘直接拷贝（不要二次预乘）。** 修复后实测：背景 alpha=0 占 46.4%、内容 alpha=255、AA 边缘 ~630 个中间值——完美的逐像素透明梯度。

> 推论：设计文档 §5.3 提到的"CPU 侧转预乘"步骤在真实语义下**不需要**——引擎输出的就是预乘结果，反而要避免二次预乘。

## 排查/迭代期间确认的工程要点

- `r.PostProcessing.PropagateAlpha` 在 5.6+ 为 bool（旧值 `2` 自动转换并回写 ini），即项目设置里的 **Alpha Output** 开关；本管线**必须打开**。
- 该语义下 BasePass 不写 alpha，透明度信息在场景合成（ComposeSeparateTranslucency 等）阶段产生；`ShowFlags.PostProcessing=false` 会得到全 0 alpha（无意义），不能这么用。
- `BuildSettingsVersion.V5` 与共享引擎产物冲突 → Target.cs 用 `Latest`。
- `TUniquePtr<前置声明类型>` 成员被 UHT 生成代码实例化析构 → 分层窗口成员改裸指针手动管理。
- `t.IdleWhenNotForeground` 是 cheat 级 cvar，写 ini 会 ensure，且实测不需要（隐藏窗仍满速渲染）。
- 灯光 `CastShadows` / 球体 `CastShadow` 关闭（无接收面，阴影只污染 alpha）；capture 的 Fog/VolumetricFog/Cloud/SkyLighting showflags 关闭（保证背景纯 a=0）。
- 材质 MID 的父材质要用 `/Engine/BasicShapes/BasicShapeMaterial_Inst`；直接用 `BasicShapeMaterial` 创建 MID 会丢参数映射，Color 不生效。
- `ConstructorHelpers::FObjectFinder` 只能在构造函数用（BeginPlay 里用会 fatal）。
- 迭代前先 `taskkill` 残留 UnrealEditor.exe，否则链接器因 DLL 占用失败。
